# Distill

## Quick start

1. 确认来源：当前/历史 agent 会话，或工作/项目过程。
2. 更具workflow提炼可复用产物。
3. 按适用范围归类：通用 skill 先确认位置。
4. 不复制原文，抽象为触发条件、决策流程、检查清单、模板。
5. 校验路径、索引、frontmatter 和产物一致性。

## Workflow

任何需要沉淀的经历——agent 会话或人的工作过程——都按以下步骤提炼。

### 1. 回放过程，收集原料

按时间轴还原关键节点、动作和产出，区分事实与判断，用标签标记：顺利、卡顿、踩坑。收拢所有中间产物（模板、话术、代码片段、检查清单）。

**完成标准**：关键节点无遗漏，原料足以支撑下一步分析。

### 2. 深挖规律，提炼经验

对成功点追问可复制条件，提炼为原则或检查清单；对失败点用 5 Whys 追到流程或机制；总结“重做一遍的最优路径”。

**针对 Agent 会话**：抽象触发条件、决策流程、常见陷阱、检查清单，不要粘贴聊天记录。

**完成标准**：至少形成一条可复用原则、检查清单或最优路径。

### 3. 封装成果，打磨工具

检查现有工具能否增强（自动校验、示例）；新建模板、清单、资源包、脚本或 skill；统一命名和存放。

**产物与范围**：

| 用户意图 | 产物 | 默认位置 |
|---|---|---|
| 整理项目协议/配置/UI/操作约定 | 项目文档 | `<project>/docs/<topic>/` |
| 提炼可复用 agent 能力 | skill | 项目级：`<project>/.agents/skills/<name>`；通用：用户指定的 skill 仓库 |
| 记录教训、流程、决策 | note | 用户指定的 notes / wiki 目录 |
| 验收、发布、复现前检查 | 检查清单 | 随文档或 skill 附在 `## Checklist` |

**完成标准**：新工具或 v2 版本能直接降低下次使用门槛。

### 4. 输出流程，固化产物

把产物写成可执行形式：说明适用边界、核心步骤、检查点、常见异常。用文档或流程图记录主路径，请不熟悉此事的人通读或试跑，根据反馈修订。

**针对 Agent 会话**：

- 若 `AGENTS.md` 由工具托管或没有索引区，不要硬改托管块；先询问用户。
- 若项目存在 `CONTEXT.md`，术语与分类文档应互相链接。
- 通用 skill 跨项目复用时，先在目标 skills 目录查重；能力相同则更新，不同则新建。未指定位置时必须询问用户。
- 写入 `SKILL.md` 格式：frontmatter + Quick start + Workflow + Lessons learned + Checklist。

**完成标准**：产物结构清晰，新人照着做能达到 80 分。复盘提问清单见 [REFERENCE.md](./REFERENCE.md)。

## 校验

- [ ] 路径正确，文件非空。
- [ ] skill 的 description 包含 `Use when ...`。
- [ ] 没有提交真实密钥或敏感信息。
- [ ] 主文件控制在 100 行内；超出则拆 `REFERENCE.md` / `EXAMPLES.md`。
- [ ] 产物已区分事实/判断。
- [ ] 产物已按适用范围归类：项目专用 / 通用，且通用产物已确认存放位置。

## Lessons learned

- 项目文档和通用 skill 不要混存。项目文档随仓库走；通用 skill 若用户未指定位置，需要显式确认目标仓库。
- 示例配置中的 API key 用占位符如 `PLACEHOLDER`，不要用 `sk-...` 等形似真实密钥的字符串。
- 不要直接把聊天记录粘贴成文档；要抽象为「何时查看、包含什么、如何使用」。
- 复盘时区分事实与判断，否则经验会被个别情绪或假设污染。
